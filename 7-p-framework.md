# The 7-P Due Diligence Framework

The 7-P Check is the signature framework in the source material. Its purpose is to make Web3 research repeatable rather than dependent on hype, token price or a single social-media thread.

## 1. Problem

Ask:

- What problem does the project solve?
- Who has this problem?
- Is the problem real and significant?
- Why does blockchain need to be involved?
- What happens if blockchain is removed?
- Who actually uses the product?
- Is there a working product?
- Is there evidence of revenue, adoption or meaningful activity?

A useful test from the source: **If this project had no token, would people still use the product?**

## 2. Product

Determine what has actually been built versus what has only been promised.

Check:

- Live product
- Demonstrations
- Documentation
- Product usage
- Delivery history
- Evidence of adoption or meaningful activity

A whitepaper is not evidence simply because it is called a whitepaper.

## 3. People

Do not reduce due diligence to whether a team is doxxed.

- Doxxed does not automatically mean legitimate.
- Anonymous does not automatically mean scam.
- Look for a verifiable track record and consistency across public sources.
- Check LinkedIn, GitHub, previous projects, interviews, technical contributions and public appearances.
- Compare founder claims with their public history.

## 4. Protocol

Understand the underlying system:

- Architecture
- Smart contracts
- Dependencies
- Governance
- Token role
- Value flow
- Deployed implementation

Cross-check **Website → Whitepaper → GitHub → Product → On-chain data**.

## 5. Protection

Investigate the security model and the controls that can affect users.

Check:

- Contract verification
- Ownership/admin roles
- Privileged functions
- Upgradeability
- Audit evidence
- Liquidity controls
- Attack surface
- Remediation of findings

## 6. Profit

Understand the economics rather than focusing only on price.

Check:

- Token utility
- Total supply
- Circulating supply
- Market capitalization
- FDV
- Allocations
- Treasury
- Vesting/unlocks
- Inflation/emissions
- Liquidity
- Holder concentration
- Revenue/incentives where relevant

## 7. Proof

Ask what independent evidence supports the project's claims.

Potential evidence includes:

- On-chain data
- GitHub activity
- Official announcements
- Independent audit reports
- Official partner announcements
- Product usage
- Public documentation

The objective is not to collect more claims. It is to verify the claims that matter.
