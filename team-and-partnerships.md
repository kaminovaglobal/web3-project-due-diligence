# Team, Community, Partnerships & Developer Activity

## Team Investigation

Look for:

- Verifiable identities
- Track record
- Previous projects
- LinkedIn profiles
- GitHub activity
- Interviews
- Technical contributions
- Public appearances
- Consistency across public sources

Potential red flags from the source include unverifiable identities, suspicious profiles, fake advisors, fabricated credentials, fake partnerships and little evidence of work despite large claims.

Anonymous teams are not automatically scams, but anonymity increases uncertainty and calls for stronger evidence elsewhere.

## Community & Social Media

Do not confuse followers with users.

Check:

- Engagement quality, not only follower count
- Genuine questions and criticism
- Whether the team answers hard questions
- Project history, not only recent posts
- Past promises versus actual delivery
- Repeated hype, urgency, unrealistic promises or manufactured engagement

## Partnership Verification

A logo on a website is not proof of a partnership.

If a project claims a partnership, verify the other side's evidence through:

- Official website
- Official X account
- Official blog/newsroom
- Verified announcement
- Specific nature of the relationship

## GitHub & Developer Activity

Check:

- Repositories
- Commits
- Contributors
- Pull requests
- Issues
- Releases
- Documentation
- Recent development activity

GitHub activity alone does not prove that a project is good. Code should be connected to a working product, users and evidence.
